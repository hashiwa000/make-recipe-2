# Feature Specification: 生成AIで1週間の朝夕レシピ計画

**Feature Branch**: `[001-ai-weekly-menu]`  
**Created**: 2025-10-21  
**Status**: Draft  
**Input**: ユーザー説明: "生成AIを使って、一週間のレシピ（朝と夜）を計画してくれるWebアプリを作りたい。"

## ユーザーストーリー & テスト（必須）

### P1: 「購入した材料」フリーテキスト入力からの週次献立生成

- 概要: ユーザーが購入済みの材料をフリーテキストで入力すると（例:「鶏もも500g、玉ねぎ2個、豆腐1丁、キャベツ半玉、卵6個、トマト缶1」）、それらを優先的に活用した7日×朝/夜の献立を自動生成し、カレンダー形式で閲覧できる。和洋中は混合で提示。
- 独立テスト: 材料テキスト→正規化→14件の献立が生成され、各料理に「使用した主要材料」が紐づく。
- 受け入れ条件:
  1. Given 材料テキスト, When 生成, Then 14スロットのうち80%以上で入力材料が主要食材として使用される（不足分は補完提案を表示）
  2. Given 料理カード, When クリック, Then 材料マッピング（入力材料/追加購入品）が区別表示される

### P2: 条件指定・好み反映・スロット再生成

- 概要: 予算/調理時間/カロリー/除外食材/嗜好（和・洋・中の比率）を指定でき、特定スロットのみの再生成や固定（ロック）が可能。
- 独立テスト: 条件変更→生成→条件に合う提案が出る。特定スロットのみ再生成できる。
- 受け入れ条件:
  1. Given 条件A, When 生成, Then 各料理が条件A（例: 調理時間≦20分）を満たす
  2. Given 月曜朝を固定, When 週再生成, Then 月曜朝のみ不変で他が更新

### P3: 買い物リストとエクスポート

- 概要: 1週間分の材料を集計し重複統合/カテゴリ分け（野菜・肉・調味料等）。CSV/PDFエクスポートに対応。
- 独立テスト: 生成結果→買い物リスト→カテゴリ別に数量表示→CSVダウンロード可。
- 受け入れ条件:
  1. Given 14献立, When 集計, Then 同一食材が単位換算の上で合算される
  2. Given リスト画面, When CSV出力, Then 行数=食材点数で欠損なし

### エッジケース

- 矛盾する条件（例: 低予算/高タンパク/短時間の同時要求）→ 明確な理由と代替提案を提示
- アレルゲン/除外食材の混入→ 生成時フィルタ＋出力後検証でブロック
- 単位/分量の不一致（g/個/大さじ）→ 標準化して表示
- 同一料理の過度な重複→ バラエティ制約で抑制
- LLM出力の曖昧さ/不適切表現→ 安全プロンプト＋ポスト検証で修正/再生成
- API失敗/タイムアウト→ フォールバック（短縮プラン/キャッシュ）とリトライ
- 入力材料のみでは7日×朝/夜を充足できない→ 不足食材の最小補完リストを提示し、代替案（品数削減/食材置換）も提示
- フリーテキストの曖昧な表現（「少々」「半分くらい」など）→ 標準量に丸めて注記を付与

## 要件（必須）

### 機能要件

- FR-001: フリーテキストの材料入力をパース・正規化し、週7日×朝/夜の献立を「入力材料優先」で自動生成する
- FR-002: 人数/アレルギー/嗜好/予算/調理時間/カロリーの入力とバリデーション（材料在庫と矛盾しない提案）
- FR-003: スロット単位での再生成・固定（ロック）
- FR-004: 料理詳細（材料・手順・所要時間・概算栄養の提示）。「入力材料から使用」「追加購入が必要」を区別表示
- FR-005: 買い物リストの自動集計（重複統合・カテゴリ分け・単位統一）。不足分は「追加購入リスト」として分離
- FR-006: CSV/PDFエクスポート
- FR-007: プラン保存/読込/共有リンク発行（匿名でも可）
- FR-008: プロンプト/システムメッセージの管理とバージョニング
- FR-009: 安全性対策（アレルゲン検査・免責/注意書き表示）
- FR-010: パフォーマンスSLOは現時点未設定（段階的表示・部分生成で体感改善）
- FR-011: 監査用ログ（入力条件・生成要約・再生成履歴）
- FR-012: エラー時の代替提案/部分生成での漸進的表示
- FR-013: レシピ/栄養データは LLM 完全生成＋後検証（既存DBなし）
- FR-014: LLM API プロバイダはTBD。コスト上限は現時点なしだがトークン効率を重視
- FR-015: 日本向け表示（食材名/単位は g/大さじ/小さじ等）。和洋中は混合がデフォルト
- FR-016: フリーテキスト材料の曖昧表現/俗称の正規化（例:「玉ねぎ半玉」→ 100g 目安）

### 主要エンティティ

- UserProfile: 人数・嗜好・除外・アレルギー
- Plan: 週次献立（週開始日・タイムゾーン・ロック状態）
- MealSlot: 日付/朝夜/料理参照/メモ
- Recipe: タイトル/概要/材料（IngredientRef[]）/手順/時間/栄養
- IngredientRef: 食材ID/名称/数量/単位
- ShoppingItem: 食材ID/名称/合計数量/単位/カテゴリ

## 成功指標（必須）

- SC-001: 不要トークン抑制（テンプレ最適化/材料先読み正規化/スロット別詳細化）。定量目標はTBD
- SC-002: 提案採用率（提案→確定）≥ 70%（TBD）
- SC-003: アレルゲン混入率=0、検出率≥99.9%（テストで担保）
- SC-004: 出力の重複料理比率 ≤ 15%（入力材料の活用率低下を避けつつバラエティ確保）
- SC-005: 継続利用率（Week2留存）≥ 35%（TBD）
- SC-006: 入力材料活用率 ≥ 80%（重量または品目ベース、TBD）

### メモ

- 対象地域/料理基準: 日本向け、和洋中混合で提示
- LLM/データ: 既存レシピDBなし。LLM完全生成＋検証
- コスト: 上限なし（現時点）。無駄なトークンを使わない方針
- 応答時間: 現状SLOなし（段階的表示で体感改善）
